# 文档、表格与报告

## 准备工作目录

把任务需要的文件放入 `--workspace` 指定的目录，或通过 Web UI 上传。Flora 使用相对路径访问文件。`..`、绝对路径、符号链接、`.git`、`.flora` 和当前会话状态目录不可通过文件工具访问。

工作目录应只包含允许 Agent 读取或修改的任务材料。开启命令执行后，命令具有宿主用户权限，文件工具的路径检查不会约束任意命令。

## 支持的输入

| 输入 | 提取内容 | 说明 |
| --- | --- | --- |
| TXT、MD、JSON、JSONL、XML、HTML、YAML、RST、LOG | UTF-8 文本 | 本地 HTML 按文本读取，不执行脚本 |
| PDF | 按页提取的文字 | 最多 300 页；不做 OCR；加密 PDF 需先解密 |
| DOCX | 段落与表格 | 不执行宏，不提取图片内容；复杂版式不保证还原 |
| CSV | UTF-8 表格 | 第一行为列名；表格查询要求列名唯一、非空、行宽一致 |
| XLSX | 单元格缓存值 | 最多 32 个工作表；不重新计算公式；缺少缓存的公式单元格可能为空 |

每个输入最大 8 MiB，提取文字最大 3 MiB。压缩格式会检查成员数量、单个成员、解压后总大小和压缩比。解析在独立子进程中执行，限制 512 MiB 地址空间、20 秒 CPU 和 30 秒墙钟时间。超限会明确失败，建议先拆分文档。

这些边界用于控制资源消耗；文档解析器并不等于完整系统沙箱。未知文件格式不会被伪装成成功提取。

`read_document(path)` 返回 `source_id`、标题、来源、原始内容哈希、当前文字窗口、总字符数和 `next_offset`。扫描 PDF 即使包含页面，也可能没有可提取文字；`details.ocr_performed` 始终为 false，文本字符数可用于判断是否需要另接 OCR。

## 保存的来源是什么

网页、文档、表格查询和 MCP 返回结果会进入当前会话的来源库。每条记录包含来源标识、标题、内容、原始字节、SHA-256 和创建时间。相同来源、相同原始字节会复用来源 ID；每次调用仍有各自的内核效果记录。

示例来源 ID：`src-000001`。它只在当前会话内有意义。不能把另一会话的相同编号当作相同内容，也不能从编号推断尚未读取的页面。

`read_source(source_id, offset=0, limit=6000)` 按字符分页，最大窗口 24,000 字符。`next_offset` 非空表示还有内容没有显示，不表示模型已经读过。原始文件 SHA-256 不是“全部内容已经进入模型上下文”的证明。

来源库默认上限 256 MiB，可设置为 16 MiB 至 1 GiB。达到上限后工具明确报错，不静默删除旧证据。原始内容与提取文字均计入配额。

## 网页研究

`web_search(query, limit=5)` 提供候选链接和搜索摘要；`web_fetch(url)` 实际读取页面。两者分别留存来源。报告依赖网页正文时，应读取原始页面，而不是把搜索摘要当作正文。

默认使用无需密钥的 DuckDuckGo HTML 搜索，但搜索方可能限流或要求验证。可配置 Brave、Tavily 或自己的 SearXNG；错误会返回，不会偷偷换服务或无限重试。

网页提取会排除 script/style/template 等内容，并保存标题、正文和链接。模型看到的初始窗口有限，可以使用 `read_source` 读取其余内容，包括完整链接清单。HTML 解析不是视觉布局理解；需要执行 JavaScript 的页面可使用浏览器工具。

PDF 网页会进入同一套有资源限制的 PDF 解析器。对于不支持的二进制媒体类型，`web_fetch` 会拒绝提取。

HTTP 客户端每次重定向都会重新检查目标地址，并在连接时固定已验证的 IP，保留正确的 Host 与 TLS 主机名验证。默认拒绝私有、回环、保留和本地网络地址。企业内网或测试服务需要明确打开 `allow_private` 并建议设置域名白名单。

## 精确表格统计

`table_query` 不执行任意代码或 SQL，数值计算使用 Decimal，结果以十进制字符串返回。单个数值表示最多 128 字符，十进制指数范围为 -256 至 256；在此边界内求和保留精确结果，平均数采用 34 位有效数字、half-even 舍入。默认返回 100 行，最大 500 行，通过 `next_offset` 分页，同时限制单页结果字节数。单行过大时返回 `rows_in_source: true`，应使用 `read_source` 读取保存的查询结果，不会循环返回同一个分页游标。每次查询的完整结果会保存为一个来源，包含查询条件和输入文件哈希。

参数示例：

```json
{
  "path": "sales.csv",
  "group_by": ["region"],
  "metrics": [{"op": "sum", "column": "revenue", "as": "total_revenue"}],
  "offset": 0,
  "limit": 100
}
```

可用指标：`count`、`sum`、`mean`、`min`、`max`。除 `count` 外必须指定已存在的列；`as` 控制输出字段名。`count` 统计匹配行数，不是某列非空值个数。无匹配行时，无分组的 count/sum 为 0，mean/min/max 为 null。

过滤示例：

```json
{
  "path": "sales.csv",
  "filters": [
    {"column": "region", "op": "eq", "value": "North"},
    {"column": "revenue", "op": "ge", "value": "100"}
  ]
}
```

过滤器依次取交集。`eq/ne/contains` 比较字符串表示；`gt/ge/lt/le` 使用 Decimal。非数值、缺失值、NaN、无穷大不会被默认为 0。出现这类值会明确失败，需要先决定清理规则。支持最多 20 个过滤器、20 个指标、总计 20,000 行和 256 列。

对 XLSX，空的 sheet 选择第一个工作表。日期值作为 ISO 风格字符串返回。公式使用文件中已有缓存，Flora 不声称已经重算工作簿。

## 生成有引用的报告

`write_report` 接受 Markdown 文本和来源 ID 列表：

```json
{
  "path": "analysis.md",
  "content": "# Analysis\n\nNorth revenue totals 200.00. [src-000001]",
  "source_ids": ["src-000001"]
}
```

列表必须恰好覆盖文本中的所有 `[src-编号]` 引用，不能含未知 ID 或重复 ID。工具会追加来源清单，包括标题、来源位置和哈希。没有外部事实引用的原创内容可以传入空列表。

新报告使用独占创建，不覆盖已有文件。修改旧报告必须传 `expected_sha256`，值来自最近一次完整读取；文件变化后旧哈希会失效。父目录需要先通过 `make_directory` 创建。

检查的是引用存在性与文件版本，不是每句话与来源的语义一致性，也不是全局事实正确性。摘要、推断和未解决的冲突仍需要模型清楚表达。

## 导出并交付

`export_document(source_path, output_path)` 支持：

| 来源 | 输出 | 行为 |
| --- | --- | --- |
| UTF-8 文本 / Markdown | `.docx` | 按段落与 Markdown 标题生成 Word |
| UTF-8 文本 / Markdown | `.pdf` | 生成文字 PDF，使用支持中文的 CID 字体 |
| `.csv` | `.xlsx` | 单元格按文本写入，防止 CSV 字符串被解释为公式 |

它不是完整 Markdown 排版引擎，不执行内嵌 HTML、脚本或宏，也不会复制任意图片。输出路径必须不存在。复杂数学排版、幻灯片或品牌模板可以通过自定义工具或 MCP 接入专门渲染器。

导出会登记文件哈希，并在源文件仍匹配报告记录时继承其来源列表。`artifact_status` 检查当前文件是否仍与登记的版本相同。普通 write_file/replace_text 工具产生的文本文件也会登记为 file 类型，便于从界面下载；它们没有经过报告引用检查，不能单独满足 require_report。截图登记为 screenshot 类型，也不能单独满足这一门槛。Web UI 的下载入口只提供已经登记的成果文件。
