# 多 agent 协作、持续工作与可靠性

Flora 的子 agent 不是内核里的候选程序。子 agent 是独立执行者，各自编译完整程序、选择诊断动作、记录实际效果并综合局部合约；候选程序则是在同一真实轨迹上比较的不同方案。不能把几个未经检查的模型答案当作已经验证的事实。

## 日常使用

直接运行 `flora`，输入任务即可。启动目录是工作目录；模型连接信息通过交互输入，密钥不会回显。简单问题可以由一个纯返回程序回答，不必创建工作清单或子 agent。复杂任务才需要拆分、交接、复核和持续工作。

```text
比较两个文档中的统计口径。请分别阅读，检查来源，明确分歧，生成 report.md。
```

运行过程中会显示主 agent 和实际子 agent 的模型输出、工具调用及结果。`/agents` 查看子任务；`/agent ID [OFFSET]` 阅读真实结果；`/log` 查看完整后台对话；`/work` 查看当前任务的工作状态。默认不设置累计调用、token 或时长预算，但一次请求、输出、纯计算、存储与并发仍有资源边界。

## 子任务生命周期

1. 主 agent 提供具体任务、必要上下文和所依赖的已有子任务 ID。
2. 子 agent 读取被交接的来源／文件，使用只读工具执行。依赖尚未完成时等待；依赖失败则明确阻塞，不凭空推断结果。
3. 主 agent 收集全部结果页，检查实际来源，再提交接受、阻塞或拒绝的复核记录。
4. 所有必需子任务都有复核记录，必需工作步骤已完成或明确报告阻塞后，才能最终返回。

复核只验证“结果已收齐、摘要与当前结果相符、引用确实存在”，不把研究结论判定为真。事实性结论仍需要查看实际证据；不要仅凭两个子 agent 说法一致就宣称正确。

### spawn_agent

```json
{
  "task": "读取 left.json，返回 count 字段和实际文件路径",
  "name": "Left reader",
  "context": {
    "guidance": "只分析当前工作目录提供的数据，不使用外部猜测",
    "source_ids": [],
    "files": []
  },
  "depends_on": [],
  "required": true
}
```

`context` 只接受 `guidance`、`source_ids`、`files`。来源必须已经在共享观察库里存在；文件引用是 `{path,sha256}`，哈希必须和实际文件一致。交接包含父任务目标，子 agent 不会隐式继承整个聊天记录。依赖 ID 必须属于当前父任务，不能引用未来任务，也不能把上一个用户问题的子结果冒充当前任务结果。

默认每个用户任务最多创建八个子 agent，最多三个并发。完全相同的当前任务交接会返回原来的 ID，不再创建副本。已完成的历史任务不占下一个用户问题的名额。子任务预算是独立账本；默认累计上限为 null，具体用量会保留。显式设置的上限在恢复时也不会重置。

### 读取与复核

`wait_agents(agent_ids, timeout)` 最多等待 60 秒，并返回所选子任务的实际状态与结果窗口。等待不调用模型。`read_agent(agent_id, offset, limit)` 每页最多 24,000 字符；返回 `next_offset` 时必须继续读取。返回文本是实际答案、原因、用量和限制，不包含完整内部程序日志。

`result_digest` 对应当前结果。`review_agent` 必须使用这个实际摘要，且先收齐所有页面：

```json
{
  "agent_id": "由 spawn_agent 返回的实际 ID",
  "result_digest": "由 read_agent 返回的实际摘要",
  "disposition": "accepted",
  "note": "已读取完整结果，并检查所引用的原始资料；剩余不确定性在最终答复中说明",
  "evidence": [{"source_id": "由实际读取工具返回的来源 ID"}]
}
```

`disposition` 为 `accepted`、`blocked` 或 `rejected`。未完成的子任务不能被接受为完成；没有结果的子任务只能阻塞或拒绝，摘要为空字符串，必须写明原因。复核中的 `evidence` 支持 `{source_id}` 或 `{path,sha256}`，不接受自行编造的 URL 作为已观察来源。最终返回前会重新检查引用，文件发生变化时需要重新复核。复核不是语义正确性的证明。必需子任务被阻塞／拒绝时，其原因会在结果和终端里显示，不能悄悄丢弃。

`resume_agent` 恢复原来的未完成任务、程序、轨迹与预算。它不表示改派一个新任务。已完成的子任务只返回缓存结果；未知效果必须先用外部证据解决，不能用恢复操作重发动作。

## 持久化工作清单

`read_work()` 返回当前任务的工作清单、修订号、证据和限制。`update_work(steps, expected_revision)` 用实际修订号更新；每一步都需要以下字段：

```json
{
  "id": "compare",
  "goal": "比较原始文档的统计口径",
  "status": "pending",
  "required": true,
  "evidence": [],
  "note": ""
}
```

状态是 `pending`、`running`、`completed`、`blocked`。既有必需步骤不能被删除或改为非必需；阻塞步骤必须说明缺少什么。完成步骤里的文件哈希在最终返回前重新检查，文件发生变化时该证据失效。修订号过期会拒绝更新，需要重新读取。

这里检查的是工作状态和证据引用，不是任务答案的真伪。一个没有工具需求的推理步骤可以完成而不包含文件来源；这种完成声明也不会被包装成已经验证的外部事实。观察库与工作清单分别保留完整内容，编译提示词里省略的内容仍可以通过工具读取。

## 长任务、等待与恢复

默认通用任务的运行步数与编译轮数不设置累计上限。每 32 个调度步骤，在已经提交的边界保存并继续执行；候选程序、真实轨迹、合约样本和累计预算保持连续。一次调度切片不是一个新任务，也不会为了切片本身重新向模型索取程序。

主 agent 提前返回但必需子 agent 仍在运行时，会保留这个返回边界等待现有工作，不连续请求模型来轮询。子任务完成后，需要收集和复核，不能只因为线程结束就当作证据齐全。

Ctrl+C 请求在下一安全边界暂停，正在进行的请求仍需要返回或超时。退出再运行 `flora --resume`，选择工作目录对应的记录；输入 `/resume` 继续未完成任务。保存的工具权限、模型、协议与预算保持固定。`/new` 创建新的对话，不删除旧记录。

在同一真实轨迹 epoch 上连续八轮安装程序、却没有新观察时，主／子 agent 会保存为 `stalled` 并指出没有进展。连续三次相同请求得到相同已知错误后，如果下一动作还准备重复同一个请求，会先保留错误信息并要求修复消费者／策略；若修复程序仍重复失败，则保存为空转。预期的三次错误之后正常返回或改用不同请求，不会触发这个检测。这个检测只识别一种常见空转，不是普遍的进度或正确性判定器。需要检查实际错误、改变策略或补充信息，而不是用重复恢复来掩盖问题。

## 网络与搜索恢复

默认解析目标地址并固定实际连接的 IP。私网、保留地址、回环和重定向到这些地址的访问仍会被拒绝。某些代理的 fake-IP DNS 会返回 `198.18.0.0/15`；这不是空搜索结果，而是本地连接路径与访问策略不兼容。不要设置 `allow_private:true` 来泛化开放访问。

可显式配置 HTTP CONNECT 代理和 HTTPS JSON DNS 解析器，连接依然固定到检查过的目标 IP，HTTPS 依然验证原站点域名。代理只授权该传输端点，不授权任意私网网页。DNS 解析器返回私有地址仍会被拒绝。

```json
{
  "general": {
    "network": {
      "proxy_url": "http://127.0.0.1:7890",
      "dns_over_https": "https://dns.google/resolve",
      "dns_bootstrap": ["8.8.8.8"],
      "timeout": 25
    }
  }
}
```

地址仅为配置示例：必须选择你能访问且信任的 DNS 服务和实际代理端口。DNS API 使用 HTTPS JSON `name`／`type` 请求和 `Status`／`Answer` 响应；协议参考 [Google Public DNS JSON API](https://developers.google.com/speed/public-dns/docs/doh/json)。不自动启用外部 DNS、代理或新的搜索服务。

搜索备用源也需显式配置，最多三个：

```json
{
  "general": {
    "search": {
      "provider": "duckduckgo",
      "fallbacks": [
        {"provider": "brave", "api_key_env": "BRAVE_API_KEY"},
        {"provider": "searxng", "base_url": "https://your-search.example"}
      ]
    }
  }
}
```

主搜索服务遭遇限流、挑战或已知读取失败时可以改用已配置来源，返回此前路由的失败分类。成功但没有结果的搜索不自动换源来制造结果。私网／合成 DNS 策略拒绝不会触发备用源绕过；POST 搜索结果未知时也不会自动另发一遍。主 agent 和只读子 agent 使用同样的观察与网络策略。

## 编译与上下文

编译器始终要求完整、严格 JSON 程序，并执行 IR、工具参数、轨迹锚点与迁移校验。简短提示词仍描述完整候选程序、诊断预测、假设 witness、局部合约和 revision，不以逐工具 ReAct 循环替换内核。

大于 16 KiB 的 receipt value 可以在模型提示词中省略，明确提供实际值的摘要和原始索引。省略不改变真实 journal，也不制造一个缩短后的假 value。程序可用 `read_receipt` 获取该索引的真实记录，或通过来源工具分页阅读保存内容。报告视图优先保留近期消费者故障、合约检查与完成拒绝信息；省略数量明确披露。没展示给模型的内容不能当作已知。

格式修复只针对尚未执行的模型提案，使用实际校验错误；流式中断的部分程序不会执行。使用服务真正支持的 `max_tokens_parameter`、JSON／推理配置与超时。程序语义错误仍可能需要模型重新设计消费者，不保证某个模型永远能一次编译正确。

## 状态与下一步

| 分类 | 行为 |
| --- | --- |
| `model_transport` | 检查模型端点和可用模型；实际请求和未知用量保留 |
| `program_validation` | 按错误修正程序，复用成功 receipt，不重新做已完成效果 |
| `stale_program_anchor` | 重新以实际 epoch／digest 编译，不能修改提案锚点装作通过 |
| `explicit_limit` | 用户设置的累计上限耗尽，恢复不会退还预算 |
| `no_progress` | 保存空转状态，需要新信息或不同策略 |
| `workers_pending` | 等现有子任务，不创建替代副本来隐藏失败 |
| `effect_outcome_unknown` | 用外部证据解决 journal，绝不自动重发动作 |

`/status` 显示当前状态、用量与原因；`/log` 显示真实模型／工具交互；`/work` 显示未完成工作。实际效果未知与普通已观察错误必须区分：超时不证明外部动作没有发生。

## 验证方法与核心边界

默认回归不调用收费模型，使用确定性 provider 与真实本地 journal，覆盖分页收集、任务作用域、依赖传递、阻塞、配额、恢复、文件证据失效、运行切片和网络策略。真实 API 的多模型测试入口位于代码分支 `tests/live_reliability_probe.py`，密钥通过隐藏输入提供，输出放在仓库之外。

```bash
PYTHONPATH=src python tests/live_reliability_probe.py --base-url https://your-provider.example/v1 --models MODEL_A,MODEL_B --rounds 2 --output /tmp/flora-evaluation
```

它改变每轮数据，验证实际文件和结果，而不把 `completed` 当作任务成功；研究类结果需要人工复核。难题、多 agent、工具错误和真实网络环境都应进入评估。接口拒绝连接的记录是测试阻塞，不能计为模型功能通过。

双重控制仍依据可检查的预测排他性和实际消费者边界选择信息动作；假设 witness 不能变成真实 PASS 样本。可综合合约仍从保留的实际上下文推导 PASS／FAIL／UNKNOWN，并对当前输入重新检查；过去的兼容性不证明未来环境正确。任务清单、结果复核、代理路由和格式修复都是外围可靠性机制，不能替代这两项机制。
