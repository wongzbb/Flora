# 部署、预算与可观测性

Flora 的核心是同步、单真实轨迹执行内核。多个任务可以由宿主服务分配到独立 runtime；同一个 Runtime 实例一次只允许一个 run。宿主工具是可信 Python 代码，解释器约束不能替代业务权限和进程隔离。

## 最小部署形态

本地验证使用一个 Python 进程、内存工具和 `MemoryTrace`。需要保留真实运行状态时，为每个任务使用独立 SQLite trace，并保留工具适配器版本、运行配置、模型 ID 和运行结果。

在 Web 服务中，建议将同步运行放在专用 worker 或 `asyncio.to_thread()` 中；模型和网络工具设置明确 timeout。任务队列、用户鉴权、secret manager、数据库访问权限、重试策略和报警应由现有平台提供。

不要在进程内直接把所有租户的工具注册到同一个 Runtime，再希望模型“只使用自己的工具”。每个任务的注册表必须来自已经授权的能力集合。

## 共享预算

```python
from flora.budget import Budget, BudgetLimits

budget = Budget(BudgetLimits(
    max_tool_calls=40,
    max_model_calls=6,
    max_input_tokens=80000,
    max_output_tokens=49152,
    max_wall_seconds=900,
))
print(budget.to_dict())
```

| 限制 | 默认值 | 记账说明 |
| --- | --- | --- |
| `max_tool_calls` | 200 | 真实普通动作和真实诊断均计数 |
| `max_model_calls` | 30 | 初始编译、重编译和格式修复均计数 |
| `max_input_tokens` | 200,000 | 使用供应商返回的真实计数 |
| `max_output_tokens` | 100,000 | 请求前预留，响应后按已知用量结算 |
| `max_wall_seconds` | 3,600 | 活跃预算计时；在边界检查，不抢占同步 I/O |

输出 reservation 是入场条件。如果一次编译要求 8192 输出 token，但剩余额度只有 4000，请求不会发出。要继续，需要在任务开始前选择相应输出上限，而不是在运行中绕过额度。

没有供应商 tokenizer 时，输入 token 只能在响应后获知，不能声称严格的发送前精确硬上限。响应报告超额后停止下一次请求。

usage 不可得或传输失败时，`unknown_usage_calls` 增加，输出 reservation 全额计入；未知的 input token 不被伪造为零成本结论。成本报告应保留这个不确定性。

## 纯计算成本

纯 VM 步数、合约检查、诊断假想执行和存储恢复也会消耗 CPU。它们不调用外部工具，不意味着没有成本。实验中应单独记录内部计算耗时、机器 steps、合同样本规模和总墙钟时间。

`max_steps` 是运行时推进循环上限，`pure_fuel` 是单次 VM 指令上限，`max_compile_cycles` 是程序 bundle 编译次数上限。三者不同；例如一次格式修复增加模型调用数，但不代表又完成一个工具动作。

## 日志与报告

运行结果包含状态、返回值、reason、运行步数、epoch、trace digest、budget 和 reports。报告用于解释候选安装、消费者检查、诊断评分、预测结果、冻结、修订与终止原因。

报告有数量上限；trace 才是真实效果记录的依据。不要把最后一条 model message 或经过裁剪的 reports 当作完整执行审计。

导出数据可能包含用户任务、个人信息、工具参数或业务对象。默认实现不做业务语义脱敏；部署时给数据库、导出文件和日志配置最小权限与保留期。API 密钥不应放入 IR、工具返回、任务文本或追踪数据。

## 应用级隔离

IR 不运行任意 Python，但工具 handler 仍然可以操作文件、网络和数据库。需要防止不可信工具实现影响宿主时，应放到独立进程或容器并使用系统级权限；本包没有宣传完整进程沙箱。

SQLite 的事务使本地提交有序，不给远端工具增加原子性。网络提交成功但本地结算前进程崩溃时，仍然必须核实 pending 事件。

## 升级与兼容

保存运行前，记录包版本与 IR 版本。0.1.0 仍是早期版本，不承诺将来所有检查点格式保持不变。升级前先在独立副本验证日志读取、IR 校验、工具名称与 schema，再切换真实任务。

不要直接编辑生产 trace 数据库来修复状态。使用明确 resolution 记录已核实的结果；无法迁移的旧程序可以作为参考输入重新编译，但真实事件历史不能被抹除。

## 交付验证怎样理解

交付报告记录实际运行的测试、环境与结果。离线 provider 测试使用本地受控 HTTP 服务，不构成对所有供应商兼容性的证明。离线工作流运行真实 IR、效果执行器和事件记录，但不是隐藏 benchmark 任务。

生产部署前的关键检查应围绕具体工具：权限是否正确、远端 timeout 是否设置、写入是否有幂等策略、审计能否核实中断效果、敏感返回能否持久化。无需给没有写权限的纯演示增加形式化审批流程。
