# 从一个任务开始

Flora（芙洛拉）让你把自然语言任务交给一个模型驱动的 agent。你提供模型，以及任务需要的普通 Python 函数或工作目录；它在内部生成程序、调用工具、读取结果并继续执行。日常使用不需要编写 IR、配置候选程序或实现工具适配器。

## 选择一个入口

| 你想做什么 | 从哪里开始 |
| --- | --- |
| 在终端输入任务，读取或修改一个项目 | 「安装与五分钟开始」，然后使用 `flora ask` 或 `flora chat` |
| 在 Python 应用里接入业务函数 | 「Python 快速开始」，使用 `Agent` 或 `invoke` |
| 保存连续对话并在以后继续 | 「会话、结果与恢复」，使用 `session_dir` 或 `--session` |
| 检查安装是否正常，暂时不连接模型 | 「两个离线工作流」中的 `demo` |
| 研究双重控制、消费者合约或解释器 | 后半部分「研究与内部实现」 |

默认没有可用业务工具。传入 `tools=[你的函数]` 即可接入业务能力；命令行加 `--workspace 项目路径` 可启用随包提供的文件工具。执行操作系统命令需要另外开启 `--allow-commands`。

## 一次使用包含什么

1. 配置可访问的模型服务，以及它要求的凭据。
2. 用自然语言描述任务，按需传入结构化数据和工具。
3. 接收运行进度和最终值；需要调试时查看结构化结果或会话记录。

模型生成的内部程序、候选选择、诊断额度、消费者检查、预算与事件保存由系统处理。使用者不需要先学习这些格式。若任务因预算、网络或未知工具结果停止，系统会明确返回状态，不把停止当作完成。

## 示例中的模型与离线标记

标为 `python network` 的代码会调用你配置的模型服务，需要真实模型 ID、可达 endpoint 和适用的密钥。`YOUR_MODEL_ID`、`your-provider.example` 是需要替换的占位符，不是发布包自带模型。

普通 `python` 代码块是可独立执行的本地 API 示例；`bash` 中的 `demo` 是不调用模型的确定性机制演示。文档校验会区分本地运行、模型示例语法检查和实际远程评测，不把三者混为一谈。

## 本版本的范围

Flora 提供直接使用的 Python API、单次任务与交互命令行、普通函数自动注册、标准文件工具、可选命令执行、持久会话，以及原有双重控制和可综合合约执行内核。核心运行时只需要 Python 3.11+ 标准库。

默认模型接口是非流式 Chat Completions 兼容 HTTP。模型服务由你提供，工具在宿主 Python 进程内运行。自动绑定工具不赋予额外业务权限；持久会话也不会自动恢复外部应用或机器的旧状态。

交付验证报告记录实际执行的测试。可用入口已经贯通，不等于指定模型在所有任务上都可靠；未执行的远程模型评测、官方 benchmark 与生产压测不会写成已完成结果。
