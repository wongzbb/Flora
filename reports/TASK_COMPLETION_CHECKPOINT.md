Defaults retain no automatic root obligation. Completed/blocked statuses remain model claims; this is not semantic verification. No live evidence yet shows that this change solves premature completion or excessive whole-workflow generation.

### Diagnostic insertion: all four outcomes

Harness: tests.live_mechanism_probe; seed=20261007; one round containing two variants per model; configs/deepseek-live-acceptance.json (thinking enabled, reasoning_effort=low). The two credible cutoff records are 590 and 750; dispatch is 17 minutes before the selected cutoff, hence competing commitments 573 and 733. This explicitly elicited experiment lets the model author alternatives, diagnostic, forecasts, witnesses and consumer; it does not establish spontaneous synthesis or causal benefit.

Mechanism pass requires distinct source-grounded normal commit frontiers, a positive evaluated diagnostic, actual diagnostic=true action selection, forecast feedback linked to the actual receipt, diagnostic read before the only commit, and the correct final receipt. Positive score or a normal shared read is insufficient.

- Flash variant 1: three normal candidates main/cand_a/cand_b all started with read_cutoff. Diagnostic score 1 but the read was shared with normals; no insertion. Task pass, mechanism fail.
- Flash variant 2: normal a/b frontiers committed 573/733. Diagnostic locate scored 1 and was actually inserted; real read supported linked PASS/FAIL forecast feedback, followed by the single correct commit 573. Task and mechanism pass.
- Pro variant 1: normal main began with read_cutoff while src_a/src_b committed 573/733. Positive diagnostic shared main's request; scheduler chose normal main. Task pass, mechanism fail, no insertion.
- Pro variant 2: both normal candidates started with read_cutoff; no insertion. Task pass, mechanism fail.

The prior consumer recovery probe passed read/publish for both models without replaying the successful effect, but all four runs had zero accepted revisions. The independently tested mixed-history probe tests.live_revision_probe is committed at d4b3eb51e9df6df4ae97721131d60ab7748cbc92 and has not run live. It must separately establish successful old-boundary preservation, current repair, accepted EXTEND, activation and actual execution.
